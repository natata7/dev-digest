# Task 1.0 Proofs – Data model and contracts for eval cases and agent eval runs

## Task Summary
Added the storage and contract layer for the eval pipeline: a new `eval_agent_runs` table (one row per agent run, with the system prompt and agent version snapshot), new columns on `eval_cases` (`expectation_kind`, `source_finding_id`) and `eval_runs` (`agent_run_id`, `status`), Zod contracts for expectations and the new API shapes, and an `EvalRepository`.

## What This Task Proves
- A `must_find` case and a `must_not_flag` case persist and read back through real Postgres.
- An agent run stores its prompt/version snapshot and per-case rows in one transaction; deleting the agent cascades runs and their per-case rows.
- `expected_output` accepts `{must_find, must_not_flag}` and the legacy array form; invalid ranges are rejected.
- One new migration was added; no existing migration was edited; the client contract copy is identical.
